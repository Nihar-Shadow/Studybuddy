## Overview

StudyBuddy is a fully local, privacy-first AI tutoring web application. It operates without external cloud dependencies or third-party AI APIs by delegating inference to a locally running Ollama instance serving Gemma 4 (`gemma4:e4b`).

The system couples a responsive Vanilla HTML/CSS/JS frontend (Progressive Web App with Service Worker offline capabilities) with a Node.js/Express backend, an agentic orchestration layer, flat-file JSON persistence, and a low-latency Python ↔ Ollama bridge using `httpx` and `orjson`.

## Data Flow

1. **Request Intake:** Client submits prompt, quiz answer, or image to `/chat` or `/quiz`.
2. **Context Enrichment & Cache Check:**
   - `smartCache.js` checks for existing identical or semantic matches.
   - If missing, `agentLoop.js` queries `dynamicTaxonomy.js` and `progressStore.js` to build prompt context.
3. **Inference Execution:**
   - Node dispatches inference request to `python/studybuddy_core.py` or directly to Ollama REST API.
   - Ollama runs local weights (`gemma4:e4b`).
4. **Streaming & Response:**
   - Output streamed chunk-by-chunk via SSE back to `public/scripts/` client UI.
5. **State Update:**
   - Post-response hooks update student mastery in `data/progress.json` (SM-2 calculation) and record new topics in `data/taxonomy_learned.json`.

## Conventions

- **Architecture:** Local-first, zero-cloud, privacy-preserving design.
- **Frontend:** Vanilla JavaScript, native CSS, progressive enhancement, no Node-based bundlers for client assets.
- **Backend:** CommonJS modules, async/await with robust error recovery.
- **Data Persistence:** Atomic file writes with automatic backup/restore upon corruption detection.

## Technical Debt

- [ ] **Automated Testing Suite:** Absence of unit and integration test framework (Jest/Supertest). Relies on manual scripts (`scripts/demo-verify.sh`) and benchmarks (`benchmark.js`).
- [ ] **Idempotent Seed Scripts:** `scripts/demo-seed.js` appends duplicate records if executed repeatedly.
